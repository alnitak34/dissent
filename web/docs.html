Dissent ← Live proof

Protocol overview

A neutral challenge layer for numerical claims.

Dissent does not decide whether an agent is intelligent or truthful. It enforces a public process: stake a claim, seal evidence, recompute the number with a bound deterministic rule, and settle onchain.

01

Commit

The agent binds the inputs, threshold, comparator and recomputer and escrows a reward.

02

Seal

A challenger commits to a hidden evidence hash and posts a deposit.

03

Reveal

After the delay, the evidence is revealed. The core validates it and calls the same immutable recomputer.

04

Settle

If the new value crosses the committed threshold, the challenger receives the reward and deposit.

Trust boundary

The core executes the committed contest.
The recomputer defines the claim.

Dissent is not a universal truth oracle. A production integration should use an immutable, audited and publicly verified recomputer. The core protects escrow, challenge timing, bounded evidence, gas delivery and settlement; it cannot prove that a domain formula is the right one for every real-world use.

Integration guide

Build a recomputer.

A recomputer is a small domain-specific contract. It receives the original inputs and optional challenge evidence, then returns one deterministic number. The same inputs and evidence must always return the same value. 

interface IRecomputer {
    function recompute(bytes calldata inputs, bytes calldata evidence)
        external view returns (int256 value);

    function validateEvidence(bytes calldata inputs, bytes calldata evidence)
        external view returns (bool ok, bytes32 reason);

    function scale() external pure returns (uint256);
    function domain() external pure returns (bytes32);
}

Base value

recompute(inputs, "") returns the value used when the agent creates the claim.

Challenged value

recompute(inputs, evidence) applies valid evidence and returns the value tested against the threshold.

Evidence validation

validateEvidence rejects malformed or disallowed evidence before recomputation.

Minimum security checklist

  • Return canonical ABI values on every path.
  • Accept only evidence that the recomputer can process within its declared gas limit.
  • Measure the worst valid case before choosing gas limits.
  • Keep evidence length as small and bounded as the domain permits.
  • Do not depend on the caller, block context or changing storage.
  • Use immutable, verified contracts for claims that carry economic value.

This is a test of that policy under the adapter's model, not a certification of Alnitak or proof of demand.
